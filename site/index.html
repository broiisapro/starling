How it works

One goal in, a flock out

A murmuration has no conductor: each bird follows a few local rules and the flock moves as one. Starling gives its agents the same deal — small independent lanes, checked before take-off.

  1. 01

    Plan into lanes

    The planner turns one sentence into a DAG where every task owns its own globs. Lanes are validated for overlap, so parallel work is conflict-free by construction.

    DeepSeek V4.1 Flash · DAG + globs + definition of done

  2. 02

    Fly the flock

    Each ready task gets a git worktree, a branch and its own opencode session. Prompts restate the goal, deliverables, out-of-scope and a literal definition of done. Up to N birds at once, across machines.

    opencode · worktrees · capacity scheduler

  3. 03

    Audit, then land

    Tests, a lane check and a local Qwen model judge every diff. Failures return to the same bird with exact fix instructions; passes queue up and merge in DAG order. Birds land when the branch is green.

    Local auditor · merge queue · integration branch

The open-weight story

Open weights all the way down. The judging stays home.

The hard reasoning rides DeepSeek V4.1 Flash. The high-volume judging — every audit, file summary and PR note — runs on a Qwen model on this laptop. No key required, no bill per verdict.

  • MIT weights for planning, coding and conflict resolution. One model family, from the plan to the patch.
  • Apache-2.0 locally for the auditor. Strict JSON every time, so a verdict can gate a merge without a human reading it.
  • No API key needed. Route every role through the opencode session you already pay for, or run the whole thing on Ollama with --fully-open.

Local numbers measured by tools/local-models/results on an Apple M5 with 32 GB: the warm audit path, not a marketing benchmark.

Flock mode

The laptops in the room are the cluster.

Run one command on a second Mac. It joins as a roost, takes tasks by free capacity, and disappears cleanly if a lid closes. No cloud, no shared disk, no SSH.

Hub This MacBook Pro engine · audits · merge queue
git bundle ↓ result bundle ↑
Perch M2 Air · any laptop opencode · worktree · tests

  • Git bundles, not a shared disk

    The hub ships the branch as a bundle; the perch works in its own worktree and sends the result back the same way.

  • Discovery that always works

    mDNS finds roosts on the LAN. When wifi blocks multicast, a join code and a URL are enough.

  • Heartbeats every 3 s

    A perch missing for 15 s is offline, and its running task is rescheduled with the attempt count unchanged.

  • One source of truth

    Audit and merge only ever happen on the hub's repo, so a perch can never fork history.

$ starling perch --hub http://192.168.1.20:7777 --code STAR-LING

Quickstart

Take off in three commands.

Bun 1.4+, git, and opencode. Point Starling at a repo you have already committed — it branches from a clean base and never touches your working tree.

starling · zsh
1 · install
# clone and install git clone https://github.com/broiisapro/starling.git cd starling && bun install
2 · point it at a repo
# no API key needed: detects opencode, a key, or Ollama bun run starling init bun run starling doctor
3 · fly
# plan, audit and merge bun run starling run "add dark mode and CSV export" --repo ../my-app

Add --dry-run to see the plan and lanes first. From a checkout the binary is bun run starling …; on your PATH it is just starling ….

Agent Skill

Hand the whole flock to your agent.

One line inside opencode or Claude Code and the Starling skill plans, launches and reports — without you decomposing anything.

/swarm "add dark mode, search and CSV export"

Drop skills/starling/ into .opencode/skills/starling/. The skill ships with examples, scripts and the four-step workflow.
