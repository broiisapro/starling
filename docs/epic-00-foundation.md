# Epic 00 — Foundation & frozen contracts

## Goal

Give ~23 parallel Wave 1 agents a single, trustworthy base: a Bun workspace that installs and tests in
one command, a zod-first `@starling/core` whose contracts and ports match ARCHITECTURE §6 exactly, mocks
for every port, skeleton packages/apps with their third-party dependencies pre-installed, and a
recorded demo run rich enough to drive the dashboard before the engine exists.

Precision was the priority, not features. Nothing here implements product behaviour beyond "boots".

## How it works

### Repo shape

- Root workspace (`package.json`, Bun 1.4.4 pinned in `packageManager` and `.bun-version`) with
  `packages/*` and `apps/*`. Internal dependencies use `workspace:*`; every package exports TypeScript
  source directly (`"exports": { ".": "./src/index.ts" }`), so there is no build step between packages.
- 15 packages and 3 apps exist with a placeholder export, a `tsconfig.json`, and a real test that
  imports both `@starling/core` and `@starling/core/testing`. That proves the wiring from day one and
  gives the integrator 30 passing tests before any feature lands.
- `apps/web` is a bootable Vite 8 + React 19 + Tailwind v4 app. It renders the boot page
  ("Starling — the sky is loading 🐦"), proxies `/api` → `localhost:7777`, and has an `index.ts`
  placeholder in `src/app`, `src/data`, `src/components`, `src/lib` and all eight feature folders.
- `apps/server` is a Hono app with `GET /api/health` → `{ ok: true, version }`; `apps/cli` registers
  every locked command as a stub that prints which epic will implement it.
- `fixtures/` holds a repo map, a seven-task plan, and a 252-event synthetic run generated by a
  committed script. A core test parses all of it with the production schemas.

### Lane overlap semantics

`globsOverlap(a, b)` walks two globs segment by segment:

1. Identical globs and any pattern containing `**` overlap (conservative).
2. Literal segments must be equal; literal vs pattern is tested by matching the literal.
3. Two patterns are sampled against each other and then compared structurally (literal prefix and
   suffix). Plain character classes are compared by set intersection.
4. When one pattern runs out of segments, it still overlaps if its last segment was a literal
   directory (directory semantics: `src/ui` owns `src/ui/**`).
5. Anything not provably disjoint is reported as an overlap.

The bias is deliberate: a false positive serialises one task; a false negative produces a merge
conflict. Directory semantics only apply to a literal trailing segment, so the file glob `src/*.ts`
does not swallow `src/ui/render.ts`.

### Fixtures

`fixtures/scripts/generate-launch-day.ts` builds the recorded run from the plan fixture and validates
every event with `StarlingEventSchema` before writing. The story covers: hub-only start, repo map,
seven tasks, a theme audit failure with fix instructions and a pass on attempt 2, merges in DAG order,
metrics every 5 s, a MacBook Air perch joining and taking three tasks, the Air dropping mid-task
(`node.left`), `task.migrated` back to the hub, and a green integration branch.

Regenerate with `bun fixtures/scripts/generate-launch-day.ts`.

### Root scripts

- `bun run test` → `bun test packages apps skills integrations tools evals`. Only those roots are
  scanned, so `examples/` and `fixtures/` are excluded without relying on ignore globs.
- `bun run check` → `biome check .` plus a shell loop running `tsc --noEmit -p` for every workspace.
  A loop was chosen over `tsc -b` project references because build mode wants composite projects and
  emitted declarations, while every package is source-only with `noEmit`.
- `bun run format` → `biome check --write .`.
- `bun run dev:web`, `bun run dev:server`, `bun run starling` run the apps directly.
- `bun run starling --help` lists plan/run/replay/dash/perch/flock/status/doctor/init.

## Key decisions & reasoning

- **Contracts are zod-first, types inferred.** Hand-written interfaces beside schemas drift after two
  waves. `z.infer` makes the schema the only source of truth. Additional schemas (PlanIssueCode,
  NodeStatus, StartTaskOptionsRepo, StarlingEventType) and the `StarlingEventOf<T>` helper are
  additive; no §6 field, name or literal union was changed. No contradictions in §6 were found.
- **TypeScript 5.9.3, not 7.0.2.** The repo relies on stable `--noEmit -p` type checking for 18
  workspaces. TS 7 is the new native compiler and its build-mode ergonomics are still settling; pinning
  5.9.3 avoids making every Wave 1 agent a compiler beta tester. `bun install` advertises 7.0.2, which
  is expected.
- **Explicit test roots instead of ignore globs.** `bun test` ignores `node_modules` automatically and
  accepts the uncreated roots (`skills`, `integrations`, `tools`, `evals`) without failing. This makes
  the `examples/` exclusion literal rather than pattern-based. Verified with a deliberately failing
  test placed under `examples/`.
- **Mocks behind a subpath export.** `@starling/core/testing` keeps production imports free of doubles
  and makes the Wave 1 rule ("prefer mocks over siblings") a one-line import.
- **MockRunner/MockNode schedule emissions asynchronously by default, with an immediate scheduler
  option.** Tests can either subscribe after `start()` and `await flush()` (realistic ordering) or use
  `immediateScheduler` with a `FakeClock` for fully synchronous, deterministic sequences.
- **`MockNode.simulateDeath()` blocks events immediately and rejects later calls with
  `NODE_OFFLINE`.** That is the exact shape the scheduler needs to test perch loss and rescheduling.
- **Exec is argv-only and never throws on non-zero.** `git` and `gh` legitimately exit non-zero;
  callers need `code`, `stdout`, `stderr` to decide. Timeouts are the one abnormal case that throws.
- **Cost table keys both bare and `provider/model` ids, with local models at zero.** The cost meter and
  `estimateSavedUsd` must never crash on an unknown model, so unknown ids price at zero.
- **DeepSeek prices are partly a placeholder.** Output $0.60/M and cached input $0.003/M are the given
  figures; uncached input is $0.28/M because DeepSeek's pricing page renders client-side and could not
  be read at build time. The table is the single place to correct it.
- **Web tests register happy-dom defensively.** `apps/web/bunfig.toml` preloads happy-dom for
  package-local runs, but the root `bun run test` does not load nested bunfig files, so the test file
  registers it too. `@testing-library/react` is installed; the boot test drives `react-dom/client`
  directly with `act` to avoid RTL's import-time `beforeAll` inside Bun's test callback.
- **Biome excludes `AGENTS.md` and `starling.config.example.yaml`.** Both are orchestrator-owned,
  whitespace-sensitive documents; a formatter run must not rewrite them (it did once during
  development and was reverted). `examples/`, `fixtures/`, `.orchestrator/` and JSONL logs are also
  excluded.
- **Fixture data is generated, not hand-written.** 252 events by hand would rot immediately; the script
  reads the plan fixture so task keys and dependencies cannot drift, and fails on an invalid event.

## Interfaces for future epics

Import contracts and ports from the package root, doubles from `/testing`:

```ts
import { createEventBus, StarlingError, globsOverlap, loadConfig, newId } from '@starling/core';
import type { ExecutionNode, LLM, Plan, TaskSpec } from '@starling/core';
import { MockLLM, MockNode, makePlan, makeRun } from '@starling/core/testing';
```

A ten-line test with `MockLLM` (this is the shape every Wave 1 package should use):

```ts
import { expect, test } from 'bun:test';
import { z } from 'zod';
import { MockLLM } from '@starling/core/testing';

test('the planner asks for JSON and gets a validated plan', async () => {
  const llm = new MockLLM({ responses: [{ text: '{"summary":"two tasks"}' }] });
  const res = await llm.completeJson(
    { role: 'planner', system: 'plan', messages: [{ role: 'user', content: 'goal' }] },
    z.object({ summary: z.string() }),
  );
  expect(res.parsed?.summary).toBe('two tasks');
  expect(llm.calls[0]?.role).toBe('planner');
});
```

## Deviations from plan

- **TypeScript pinned to 5.9.3** instead of the registry-latest 7.0.2 (reason above).
- **Two extra additive exports** (`withCall`, `lanesDisjoint`, `emptyUsage`) beyond the requested list;
  they keep metrics and lane logic pure and testable rather than being inlined in future epics.
- **The root test script lists roots that do not exist yet.** Bun accepts them today; when `skills/`,
  `integrations/`, `tools/` and `evals/` appear they are picked up automatically.
- **`apps/web` ships `@testing-library/react` but its boot test uses `react-dom/client` + `act`.**
  RTL's import-time `beforeAll` is incompatible with Bun's test callback model.
- **The DeepSeek uncached-input price is a documented placeholder** ($0.28/M).

## Known limitations / deferred

- Glob overlap detection is conservative and does not parse braces (`{a,b}`) or extglobs. It may report
  false positives for patterns containing `**` in the middle; it never reports a provably disjoint pair
  as overlapping.
- `globToRegExp` supports `*`, `**`, `?`, `[...]` only. Negated classes are matched but not enumerated
  during overlap checks.
- `MockWorkspace` models files as strings; it does not emulate git history, merge commits or binary
  files. Real git behaviour is the workspace epic's job.
- `MockRunner`/`MockNode` scripts are synchronous generators of events; they do not pause between
  emissions for external prompts.
- The web app is only the boot page (feature folders are placeholders). The server only exposes
  `/api/health`. The CLI only prints stubs. Everything else is explicitly out of scope for Epic 00.
- No live/network tests exist yet. The `*.live.test.ts` convention and `STARLING_LIVE` gate are
  documented in AGENTS.md for the epics that need them.
- No CI. Epic 02 owns `.github/**`.
- The recorded run is synthetic; it is not a recording of a real engine execution and should be
  replaced/regenerated once the engine can record runs.
