**Key design decisions:**
- **Split check and tests into separate Ubuntu jobs** — they run concurrently, so wall time is
  `max(check, test)` rather than their sum; the extra install is covered by the cache.
- **macOS is narrow on purpose** — only the three packages whose tests create worktrees, merge refs or
  probe the host OS. Typechecking is platform-independent and already runs on Ubuntu.
- **Cache `~/.bun/install/cache` keyed on `bun.lock`** with `restore-keys` — the lockfile is the only
  thing that invalidates the dependency set; a partial restore still helps on a dependency bump.
- **`--frozen-lockfile` everywhere** — CI must never rewrite `bun.lock`; a mismatch is a deliberate
  integrator decision (AGENTS.md §2).
- **Current action majors** (`checkout@v7`, `cache@v6`, `upload-artifact@v7`) — the v4 line
  targets deprecated Node 20 and emits a warning on every run; the current majors keep the same inputs.
- **No `paths:` filters** — workspace imports mean a change in one package can break tests in another,
  so every PR gets the full gate.
- **No live tests** — `*.live.test.ts` self-skips without `STARLING_LIVE=1`, and CI never sets it, so
  no model/opencode/GitHub call happens (L23/L29).
- **Pin guard in `check`** — `.bun-version`, `package.json#packageManager` and the workflow's
  `BUN_VERSION` cannot drift apart silently (L21).
