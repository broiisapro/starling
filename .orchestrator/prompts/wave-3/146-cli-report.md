## Goal
After a run, people want the receipt: did it work, how long did it take, how much faster than one agent doing it serially, what did it cost, and who (which laptop) did what. `starling report <run.jsonl>` turns a recording into that flight report in Markdown (for PR comments and READMEs, posted by Epic 164's GitHub Action), JSON (for tools) and a single self-contained HTML page (for sharing). Great looks like: the Markdown renders beautifully on GitHub, the numbers add up and are explained, and the same input always gives byte-identical output.

## Deliverables
1. `index.ts` exporting `extension` (`name: 'report'`) registering `starling report <run.jsonl>` with `--format md|json|html|text` (default `text` in a TTY, `md` otherwise), `--out <path>` (write the file, print the path), `--run <id>` (when the file holds several runs), `--title <text>` and `--no-color`. **Keep these flag names stable**: Epic 164's Action calls `starling report <file> --format md`.
2. `model.ts`: `buildFlightReport(events, { runId? }): FlightReport` (pure; name chosen to not clash with Epic 111's server-side `buildRunReport`). `FlightReport` has `version: 1`, run `{ id, goal, status, integrationBranch, startedAt, finishedAt, wallMs }`, `outcome: 'success' | 'partial' | 'failed' | 'cancelled' | 'running'`, task counts by final status, `tasks[]` (key, title, status, node id/name, attempts, `activeMs` from first `running` to terminal, audit verdicts count and last summary, merge status, cost, tokens), `parallelism { peak, average, timeline: { t, active }[] }` (from `task.status` transitions; active = running/auditing/fixing/merging), `serialMs` (sum of task active time), `speedup` (`serialMs / wallMs`, null when wall is 0), `cost { apiUsd, estSavedUsd, apiTokens, localTokens, localCalls }` from the last `metrics` event (fallback: sum of `TaskRun.costUsd`), `nodes[]` (id, name, tasks run, active time share, joined/left with reason), `notable[]` (failed audits, conflicts, migrations, node losses: one line each), and the `run.finished` summary.
3. Read the recording with a lenient reader (C1 rule) and derive run snapshots yourself (or via `deriveRunState` from `packages/store/src/index.ts`, fed only the events it knows); the report must work on a run that never finished (outcome `running`, wall time to the last event).
4. `markdown.ts`: `renderMarkdown(report, { title? })` → GitHub-flavoured: a one-line outcome header with emoji (🐦 success / ⚠️ partial / ❌ failed), a key-numbers table (wall, serial, speedup ×, peak parallel, tasks merged/failed, API cost, saved), a per-task table, a per-node table, "Notable" bullets, the summary as a blockquote, and a `<details>` block with a tiny ASCII parallelism sparkline. No raw HTML other than `<details>/<summary>`; every value from the recording is escaped for Markdown (pipes, backticks, `<`).
5. `html.ts`: `renderHtml(report)` → one self-contained file: inline CSS (light and dark via `prefers-color-scheme`), no scripts, no external URLs, an inline SVG parallelism chart. **All recording text is HTML-escaped** (model output can contain markup; Epic 157 is probing XSS). Readable printed.
6. `text.ts`: the terminal version (coloured, fits `columns`), reusing copied `renderTable`/`fmtDuration`/`fmtUsd` helpers.
7. `json` format: `JSON.stringify(report, null, 2)` with stable key order; numbers rounded (ms integers, USD 4 decimals).
8. Determinism: no `Date.now()` or locale-dependent formatting in output (format times as elapsed `m:ss` and ISO UTC); same input → byte-identical output (test it).
9. `try.ts`: `bun apps/cli/src/ext/report/try.ts fixtures/runs/sky-todo-launch-day.jsonl --format md`.
10. Tests (≥ 35): model over the fixture (7 merged, speedup > 1, peak parallel, `air` left, `search` migrated, `theme` 2 attempts, cost equals the last metrics event); hand-made runs: failed task → partial, all failed → failed, cancelled, unfinished (running), zero tasks, single task (speedup ≈ 1); markdown escaping of a goal containing `|`, backticks and `<script>`; HTML contains no `<script` and escapes `<`; snapshots of md/text/html for the fixture; `--out` writes the file; multi-run file needs `--run`; unknown events skipped.
