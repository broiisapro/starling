## Goal
Give the terminal its own murmuration. `starling watch` follows a run (live from the server's SSE stream, or from a JSONL recording) and redraws one compact screen in place: a little sky where each task is a bird glyph that takes off, circles and roosts as its status changes, a task table, the merge queue, node roster and cost. It's what a presenter leaves running in a second terminal, and what someone on SSH sees instead of the dashboard. Great looks like: smooth at 4 fps, never flickers, survives a server restart by reconnecting, degrades to clean append-only lines when piped, and exits with a one-line summary when the run finishes.

## Deliverables
1. `index.ts` exporting `extension` (`name: 'watch'`) that registers `starling watch [runId]` with `--url <url>`, `--token <t>`, `--file <run.jsonl>`, `--speed <n>` (file playback multiplier, default 8; `0` means "no delays, render the final frame"), `--follow` (with `--file`: keep tailing a file that `starling run --record` is still writing), `--ascii` (no emoji/box glyphs; also automatic when `TERM=dumb`), `--once` (print one frame and exit), `--fps <n>` (1–8, default 4) and `--no-color`.
2. `events-io.ts` (copied pattern, see the C1 rule): `parseEventsLenient(text, source): { events: StarlingEvent[]; skipped: number }`, `readEventsLenient(path)`, and `tailFile(path, onEvent, { signal, pollMs })` that polls size growth (no `fs.watch`; partial last lines are buffered until the newline arrives).
3. `sse-client.ts`: `followSse(url, { fetch, token, since, signal, onEvent, onStatus, sleep }): Promise<void>` reading `response.body` with a `TextDecoder`, splitting on blank lines, ignoring comment frames, tracking the last `ts`, and reconnecting with `?since=<lastTs>` on a dropped stream using capped backoff (250 ms → 4 s). It dedupes events already seen at the same `ts` (same key rule as `apps/server/src/sse.ts`'s `eventKey`). `onStatus` reports `connecting | live | reconnecting | ended`.
4. `watch-state.ts`: a pure reducer `applyWatchEvent(state, event)` over `run.created`, `plan.created`, `task.status`, `audit.verdict`, `merge.result`, `metrics`, `node.joined|left|stats`, `task.migrated`, `log`, `run.finished`, plus `run.status` **when present** (feature-detect on `event.type` as a string so it compiles before and after Epic 40). It keeps a recent-activity ring (last 8 lines) and per-task "last action". Never throws on unknown or out-of-order events.
5. `sky.ts`: `renderSky(state, { width, height, tick, ascii }): string[]`. Each task is a bird: `pending/ready` perched on the ground row, `running/fixing` flying in a band that drifts with `tick` (deterministic, seeded by task key: no `Math.random`), `auditing` hovering near the roost, `merging` in a queue line at the roost, `merged` roosted (✓), `failed/conflict` fallen (✗). Glyph sets: `🐦 · ✓ ✗` and the ASCII set `v . + x`. Node colour per bird when colour is on.
6. `frame.ts`: `renderWatchFrame(state, { width, height, palette, tick, ascii, connection }): string` composing header (run id, status, elapsed, connection badge), the sky (about 6 rows), a task table (status, key, node, attempts, duration, last action; truncated to fit `height`), merge queue order, nodes (online/offline, slots), and cost line (`apiCostUsd`, `estSavedUsd`, tokens). It never exceeds `width` visible columns (ANSI-aware) and never exceeds `height` rows.
7. `driver.ts`: TTY mode redraws in place (hide cursor, cursor-up + `\x1b[2K` per line, clear leftovers; copy the approach of `apps/cli/src/live-view.ts`), throttled to `--fps` with a forced final frame; restores the cursor on exit, on `SIGINT` and on errors. Non-TTY mode prints one plain line per meaningful change (`12:03 theme running → auditing on hub`) and no escape codes.
8. Run selection: with no `runId`, pick the newest run from `GET /api/runs` (by `startedAt`), or the only run in the file; with several runs in a file and no id, use the last `run.created`. Unknown id → exit 2 with the known ids listed.
9. Exit behaviour: on `run.finished` print the final frame plus a one-line summary (merged/failed, wall time, cost) and exit 0 (1 if the run status is `failed`/`cancelled`); server unreachable at start → exit 1 with a hint (`is "starling dash" running? try --file`).
10. `try.ts`: `bun apps/cli/src/ext/watch/try.ts --file fixtures/runs/sky-todo-launch-day.jsonl --speed 40`.
11. Tests (≥ 35): reducer over the whole fixture (final statuses, migration reflected, verdict count), lenient parser (unknown type skipped, bad JSON line number), `tailFile` with a file appended in steps, SSE client against a `Bun.serve` on `127.0.0.1:0` that sends a backlog, drops the connection and checks the reconnect carries `since`, sky determinism (same tick → identical rows; ASCII set has no non-ASCII chars), frame width/height bounds at 60/100/160 columns, non-TTY output has no `\x1b`, `--once` output snapshot with colour off, commander parsing.
