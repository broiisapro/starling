## Goal
Most people who'd use Starling live in an editor. A tiny VS Code extension makes the flock ambient: a status bar item that shows `🐦 3 perches · 12/30` while a run flies, a **Starling: Run goal** command that asks for a goal and launches the CLI in a terminal, and **Starling: Open dashboard**, which shows the murmuration in a webview next to your code. It ships with zero dependencies: a hand-written `vscode` type shim, Bun to bundle, and pure modules that are unit-tested. Great looks like: a reviewer opens the folder with `code --extensionDevelopmentPath=integrations/vscode`, runs the command, and sees the Sky inside VS Code.

## Deliverables
1. **Manifest** `integrations/vscode/package.json`: `name: "starling-vscode"`, `displayName`, `publisher: "starling"`, `version: "0.1.0"`, `private: true`, `license: "MIT"`, `engines.vscode: "^1.90.0"`, `main: "./dist/extension.js"`, `activationEvents: ["onStartupFinished"]`, `contributes.commands` (`starling.runGoal` "Starling: Run goal", `starling.planGoal` "Starling: Plan goal (dry run)", `starling.openDashboard` "Starling: Open dashboard", `starling.refreshStatus`) and `contributes.configuration` (`starling.serverUrl` default `http://127.0.0.1:7777`, `starling.cliPath` default `""` = auto, `starling.token` default `""`, `starling.pollSeconds` default 3). **No `dependencies` or `devDependencies` keys at all**, and no `scripts` that install anything (L34). Confirm `bun install` at the root leaves `bun.lock` untouched (the folder isn't a workspace member).
2. **Type shim** `src/vscode.d.ts`: `declare module 'vscode' { … }` covering only what you use (`ExtensionContext`, `Disposable`, `window.createStatusBarItem`/`showInputBox`/`showErrorMessage`/`createWebviewPanel`/`createTerminal`/`createOutputChannel`, `StatusBarAlignment`, `ViewColumn`, `commands.registerCommand`/`executeCommand`, `workspace.getConfiguration`/`workspaceFolders`/`onDidChangeConfiguration`, `Uri.parse`, `env.openExternal`/`asExternalUri`). Keep it small and honest about what it covers.
3. **Status (pure)** `src/status.ts`: `fetchFlockStatus(fetchFn, { serverUrl, token, timeoutMs }): Promise<FlockStatus>` (`GET /api/nodes` + `GET /api/runs`, newest active run, send `x-flock-token` when set, never throw: `{ state: 'offline' }` on any error) and `formatStatusBar(s): { text: string; tooltip: string }` (`$(radio-tower) 🐦 3 · 12/30`, `$(debug-disconnect) Starling offline`, done `✓ 30/30`). In-flight = `running | auditing | fixing | merging`.
4. **CLI resolution and argv (pure)** `src/cli.ts`: `resolveCli({ setting, env, workspaceRoot, exists }): { command: string; args: string[] }` (setting → `$STARLING_BIN` → `starling` on PATH → `bun <root>/apps/cli/src/index.ts` when the workspace is a Starling checkout) and `runGoalArgv(goal, { repo, dryRun, maxParallel }): string[]` (validated: non-empty goal ≤ 2 000 chars, no NUL; flags exactly as `starling run --help` names them).
5. **Running without a shell:** launch with `window.createTerminal({ name: 'Starling', shellPath: command, shellArgs: argv, cwd })`, so the goal text is never pasted into a shell (no `sendText` with user input).
6. **Dashboard webview (pure HTML)** `src/webview.ts`: `dashboardHtml({ url, nonce, cspSource }): string` → an iframe to the dashboard URL (passed through `env.asExternalUri` in `extension.ts` so Remote/Codespaces work) with a strict CSP (`default-src 'none'; frame-src <origin>; style-src 'nonce-…'`), the URL attribute-escaped, and a friendly "Starling isn't running: start it with `starling dash`" fallback panel when the status is offline.
7. **Glue** `src/extension.ts`: `export function activate(ctx: ExtensionContext): void` / `deactivate()` — registers the commands, owns one status bar item and a poll timer (cleared on deactivate and on config change), and logs to an output channel. Runtime `vscode` comes from the host via `require`. **The extension host is Node, not Bun**, so no `Bun.*` in `src/`.
8. **Build** `integrations/vscode/build.ts`: `Bun.build({ entrypoints: ['src/extension.ts'], target: 'node', format: 'cjs', external: ['vscode'], outdir: 'dist', minify: false })`; `dist/` stays untracked (root `.gitignore` already ignores it). `README.md`: run from source (F5 or `code --extensionDevelopmentPath=…`), packaging with `npx @vscode/vsce package` (documented, not run), settings, and a screenshot slot.
9. **Tests** (`bun test integrations/vscode`): status formatting and the fetch fallbacks with a fake `fetch`, CLI resolution order, argv validation, webview CSP and escaping (`"><script>` in the URL), manifest checks (commands referenced in code exist in `contributes`, no dependency keys), and an activation test using `mock.module('vscode', …)` with a fake host that asserts four commands and one status item are registered and everything is disposed on `deactivate`. At least 25 tests, under 3 s.
