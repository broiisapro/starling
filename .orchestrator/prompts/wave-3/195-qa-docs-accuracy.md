## Goal
Judges and new contributors read the README first, and ~100 agents read `docs/epic-*.md` "Interfaces for future epics" as gospel. Every stale flag, renamed env var, missing route or dead link costs someone an hour. Build a reusable, deterministic docs checker that extracts every CLI command and flag, env var, HTTP route, relative path/link, `bun run` script, config key and exported symbol mentioned in Markdown, and checks each against the real code. Then report the mismatches as FIX REQUESTS to each doc's owner. Great looks like a checker with solid unit tests, a generated mismatch report, and test.todos for confirmed mismatches. It must not fail the build when other agents add docs in parallel.

## Deliverables
1. **`extract.ts` — pure extractors (no I/O).** `extractCommands(md)` → `{ cmd: string[], flags: string[], line }` from fenced `sh|bash|console` blocks and inline code starting with `starling ` (handles `\` continuations, `$(...)`, quoted args, `--flag=value`, `--no-x`); `extractEnvVars(md)` for `STARLING_*|OPENCODE_*|DEEPSEEK_*`; `extractRoutes(md)` → `{ method?, path }` for `/api/...` and `/perch/...` (normalise `:id`/`<id>`/`{id}`); `extractLinks(md)` for relative Markdown links/images and backticked repo paths (`packages/x/src/y.ts`, skipping globs and placeholders like `<name>`); `extractScripts(md)` for `bun run <script>`; `extractYamlConfigBlocks(md)`; `extractExports(md)` for `export function|const|class|interface|type Name` lines inside ts blocks under an "Interfaces for future epics" heading, with the package inferred from the doc/section.
2. **`truth.ts` — ground truth from code (read-only imports).** CLI tree from `createProgram()` in `../../../apps/cli/src/program.ts` (walk `program.commands` and each `.options` long names; accept commander's `--no-` forms); pending CLI extensions from `apps/cli/src/ext/*/index.ts` (`extension.name`), classified **pending C3 wiring** rather than missing; env vars from a scan of `packages apps tools skills integrations` `*.ts`; routes from `app.get|post|put|delete('…')` registrations in `apps/server/src` and `packages/perch/src` plus the ARCHITECTURE §6 tables; scripts from every `package.json`; exports from `Object.keys(await import(index))` for each `packages/*/src/index.ts` (types can't be seen at runtime: check them with a regex over `index.ts` and the re-exported files).
3. **`check.ts` — the checker + CLI.** `checkDocs({ root, files? }) → Finding[]` with `{ file, line, kind: 'command'|'flag'|'env'|'route'|'path'|'script'|'config'|'export', value, status: 'ok'|'missing'|'pending-c3'|'ambiguous', hint }`; `bun tools/qa/docs/check.ts [--json] [--kind route]` prints a grouped table and exits 0 always (it reports, it never gates). Scans `README.md`, `CONTRIBUTING.md`, `AGENTS.md`, `docs/**/*.md`, `skills/**/*.md`, `examples/**/README.md`, `site/README.md`, `apps/*/README.md`, skipping `node_modules`, `.orchestrator/` and `docs/blog/`.
4. **`extract.test.ts` (~25).** Synthetic Markdown fixtures for each extractor: multi-line commands, flags with values, `--no-` flags, env vars inside prose vs code, routes with each param style, links with anchors and `../`, absolute URLs ignored, placeholders ignored, code fences in lists, nested backticks, CRLF files.
5. **`truth.test.ts` (~8).** The CLI tree contains `run`, `plan`, `replay`, `dash`, `perch`, `flock`, `status`, `doctor`, `init` with the flags registered in `program.ts` (`--max-parallel`, `--fully-open`, `--record`, `--json`, `--yes`, `--no-flock`, …); route truth contains every row of the §6 tables; export truth for `@starling/core` contains `loadConfig`, `StarlingEventSchema`, `createEventBus`.
