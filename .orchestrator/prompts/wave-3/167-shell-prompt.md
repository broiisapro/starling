## Goal
A tiny, delightful touch: while a run is flying, your shell prompt shows `🐦 12/30` (birds in flight / tasks), then `🐦 ✓30` when it lands. It works in zsh, bash and fish and must **never** slow the prompt down: the prompt only reads a cache file, a background refresh talks to the hub, and when the hub is down the segment just disappears. Great looks like: three copy-paste snippets in the README, a `starling-prompt` script that answers from cache with no network, and tests that prove the format, the run picking and the cache behaviour.

## Deliverables
1. **Pure core** `integrations/shell/segment.ts`: `pickRun(runs: Run[], now: number): Run | undefined` (newest run in `mapping | planning | planned | running`; otherwise the newest finished within the last 10 minutes); `countTasks(run): { inFlight: number; done: number; failed: number; total: number }` (in flight = `running | auditing | fixing | merging`; done = `merged`; failed = `failed | conflict`); `formatSegment(c, opts: { ascii?: boolean; finished?: boolean; style?: 'plain' | 'zsh' | 'bash' }): string` → `🐦 12/30`, `🐦 12/30 ✗2`, `🐦 ✓30`, ASCII `st 12/30`, and `''` when there is nothing to show. Prompt escapes per shell (`%{…%}` for zsh, `\[…\]` for bash) only when colour is on.
2. **Cache** `cache.ts`: path `${XDG_CACHE_HOME:-~/.cache}/starling/prompt-<8-hex hash of server URL>.txt` holding just the rendered segment, plus a sibling `.json` with `{ updatedAt, failures }`. Writes are atomic (temp file + rename). Read helpers never throw.
3. **Refresh** `refresh.ts`: `refresh({ serverUrl, token?, fetch, now, cacheDir, timeoutMs = 300 })` → `GET /api/runs` (send `x-flock-token` if configured), `pickRun`, `formatSegment`, write the cache; on any failure write `''` and back off exponentially (failures in the json; max 60 s between attempts) so a dead hub costs nothing.
4. **CLI** `starling-prompt.ts` (+ an executable `starling-prompt` sh shim calling `bun` on it): `starling-prompt [--refresh] [--ascii] [--server URL] [--style zsh|bash|plain]`. Without `--refresh` it **only reads the cache** and prints it (no network, no imports of server code). `--refresh` performs one refresh and exits.
5. **Shell snippets** that never block and never fork in the foreground except a backgrounded refresh, throttled to once every 2 s: `starling.zsh` (`zmodload zsh/datetime`, `precmd` hook, `$EPOCHSECONDS`, reads the cache with `$(<file)`, background `( starling-prompt --refresh >/dev/null 2>&1 & )`, exposes `$STARLING_PROMPT` for the user's `PROMPT`/`RPROMPT`), `starling.bash` (bash 3.2 compatible for macOS: `PROMPT_COMMAND` chaining that preserves the user's existing command, `$SECONDS` throttling, `read -r` from the cache), `starling.fish` (`function starling_prompt_segment`, used from `fish_right_prompt`, `--on-event fish_prompt` refresh).
6. **Opt-outs:** `STARLING_PROMPT=off` disables everything; `STARLING_PROMPT_ASCII=1` switches to ASCII; respects `NO_COLOR`.
7. **README.md:** the three install snippets (one line each to `source`), what the numbers mean, the opt-outs, and a "why it's fast" note (cache only, background refresh, backoff).
8. **Tests:** run picking over hand-made `Run` lists (active vs finished vs stale), counts per status, every format variant including ASCII and both escape styles, cache round trip and atomic write in a temp dir, refresh success/failure/backoff with a fake `fetch` and clock, the CLI read path makes **zero** fetch calls (inject a throwing fetch), and syntax checks of the snippets with `zsh -n`, `bash -n`, `fish -n` each guarded by `test.skipIf(!Bun.which('<shell>'))`. Run the bash snippet for real in `bash --norc -i -c` with a fake cache to assert that `PROMPT_COMMAND` exports `STARLING_PROMPT`. At least 25 tests, under 3 s.
