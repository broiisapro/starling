## Goal
With 100 agents on one laptop, wall-clock benchmarks flake, but an accidental O(n²) or a git call per file still turns a 7-minute demo into 20. Pin the cost of package hot paths with **non-flaky** budgets: counts of git/exec invocations (via injected `exec` spies), LLM calls, bus events and store rows, plus output sizes (rendered map tokens, prompt chars, patch bytes, DB bytes per event). Great looks like a typed `budgets.ts` with each budget set about 2× today's measurement, ~35 budget tests that only fail on real regressions, and a report-only benchmark script for humans.

## Deliverables
1. **`budgets.ts`.** `export const BUDGETS = { 'repomap.map.gitCalls': { max: N, measured: n, note }, … } as const` covering every test below; each `max` ≈ 2× the measured value (rounded) or a documented constant (e.g. `DEFAULT_MAX_CHARS`). `support.ts` provides `spyExec(real = exec)` (counts calls by argv[0..1], e.g. `git ls-files`), `syntheticRepo(files)` (git init + one commit of generated files), `syntheticMap(n)` via `makeRepoMap`, `syntheticPlan(n, { overlap })` via `makePlan`/`makeTaskSpec`, and `expectWithin(key, value)` that also prints the measured value.
2. **`repomap.test.ts` (~6).** `createRepoMapper({ exec: spyExec() }).map(syntheticRepo(2_000))`: git invocations are a small constant (not per file); `map.tree.length ≤ 4000`; `renderRepoMap(syntheticMap(n), { maxTokens })` gives `estimateTokens(output) ≤ maxTokens` for n = 10, 1,000, 10,000; `rankRepoFiles` output size is bounded by its options; `samplePaths(paths, max)` returns ≤ max. (Timing benchmarks for 10k-file repos are Epic 108's: don't add any.)
3. **`planner-prompts.test.ts` (~7).** `validatePlan(syntheticPlan(100 | 300))` returns, and the number of `lane-overlap` issues ≤ number of unordered task pairs (each pair reported once); `createPlanner({ llm: MockLLM })` makes exactly 1 call for a valid plan and ≤ `1 + maxRepairs` for invalid ones; the planner prompt for a 10,000-file map stays within `mapTokens` (default 3000) for the map block; `createPromptCompiler().worker` ≤ `DEFAULT_MAX_CHARS` and its map section ≤ `DEFAULT_MAX_REPO_MAP_CHARS` for 300-task plans; `fixer` with 100 failed checks ≤ `DEFAULT_MAX_CHARS`.
4. **`workspace-merger.test.ts` (~7, small real repos with `spyExec`).** git calls per `create`, `diff`, `changedFiles`, `commitAll`, `predictConflicts`, `remove` are constants independent of the number of changed files (measure at 5 and 500 changed files: equal counts, or report the per-file loop as a finding); `diff` of a 5 MB change keeps `patch` ≤ `PATCH_LIMIT_BYTES`; merger `preflight` and a clean `merge` use ≤ budget git calls; `createMergeQueue` adds no extra merge calls (n enqueues → n merges).
5. **`store.test.ts` (~5).** `appendEvents` of 50,000 synthetic events into a temp-file SQLite store: file size ≤ 2× the JSONL byte size; `events(runId)` returns 50,000; `events(runId, since)` returns exactly the tail; `listRuns` with 1,000 saved runs returns 1,000; `serialiseJsonl` output bytes ≈ sum of `JSON.stringify` lengths + newlines.
6. **`engine-bus.test.ts` (~5).** Engine on core fakes (minimal harness copied into `support.ts`) with a 10-task plan: non-agent bus events per task ≤ budget; `metrics` events are throttled by `MetricsPublisher` (≤ one per timer tick on fake timers, not one per event); `store.appendEvent` calls vs bus events (Epic 70 F3 double persistence: known todo when you also attach a recorder); `run.finished` exactly once.
7. **`auditor-core.test.ts` (~4).** `prioritiseDiff` on a 10 MB patch returns ≤ `maxChars`; `tailText` on 50 MB of output keeps ≤ `COMMAND_OUTPUT_TAIL_CHARS`; `globsOverlap` on 100 lanes × 10 globs completes inside a generous per-test timeout (`test(…, 20_000)`) and reports a deterministic overlap count; `checkLane` on 10,000 files is linear in calls (no per-pair expansion).
8. **`bench.ts` (report-only).** `bun tools/qa/perf/bench.ts` runs the same scenarios with `performance.now()` and prints a table of ms + counts. It is never imported by a test and asserts nothing about time.
