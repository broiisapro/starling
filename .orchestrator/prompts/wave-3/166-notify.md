## Goal
A Starling run takes ten minutes to an hour, and nobody watches the dashboard the whole time. A small notifier follows the hub's event stream and posts the moments that matter (run started with N tasks, first merge, an audit failure with its reason, a perch joining or leaving, run finished with merged/failed counts, time and cost) to a Slack- or Discord-compatible webhook or as macOS notifications. It's rate-limited so a 30-task run doesn't spam a channel, it reconnects without losing or repeating events, and it has a dry-run printer for demos and tests. Great looks like: `bun integrations/notify/notify.ts --file fixtures/runs/sky-todo-launch-day.jsonl --dry-run` prints about ten crisp, emoji-light messages that tell the whole story of the run.

## Deliverables
1. **Milestones (pure)** `milestones.ts`: `export type Milestone = { kind: 'run-started' | 'plan-ready' | 'first-merge' | 'merged' | 'audit-failed' | 'task-failed' | 'conflict' | 'node-joined' | 'node-left' | 'budget-warning' | 'run-finished'; runId: string; ts: number; title: string; body: string; severity: 'info' | 'good' | 'warn' | 'bad'; taskKey?: string }`; `createMilestoneTracker(): { push(e: StarlingEvent): Milestone[] }`, a reducer over the event contract (`run.created`, `plan.created`, `task.status`, `audit.verdict`, `merge.result`, `node.joined`/`node.left`, `log` warn/error, `metrics`, `run.finished`). Read the payload shapes in `packages/core/src/contracts.ts`. The final message carries merged/failed/conflict counts, wall time, cost and saved-vs-API from the last `metrics` event.
2. **Rate limiting and coalescing (pure)** `limiter.ts`: a token bucket (`ratePerMin`, `burst`; defaults 6/min, burst 3) with an injected clock; overflowing `merged` milestones fold into one digest ("+5 more tasks merged: …"); `bad` milestones and `run-finished` are never dropped (they may wait); `flush()` at shutdown.
3. **Formatters (pure)** `format.ts`: `toSlack(m)` (`{ text, blocks? }`), `toDiscord(m)` (`{ content, embeds: [{ title, description, color }] }`), `toGeneric(m)` (the milestone JSON), `toTerminal(m, { color })` for dry runs. Every model-produced string (audit reasons, task titles) is truncated (≤ 300 chars) and escaped for the target (`<`, `>`, `&` for Slack; `@everyone`/`@here` and mentions neutralised for Discord).
4. **Sinks** `sinks.ts`: `webhookSink({ url, format, fetch, retry })` (POST JSON with a 5 s timeout; 429 → honour `Retry-After`; 5xx → bounded backoff; never logs the URL, which is a secret: print `hooks.slack.com/…/****`); `macosSink({ exec })` → `osascript -e 'display notification … with title …'` via an **argv array** with AppleScript string escaping (quotes and backslashes), `platform !== 'darwin'` → a clear error; `printSink(write)` for `--dry-run`.
5. **Event sources** `source.ts`: `followSse({ url, token?, fetch, since?, signal, onEvent, reconnect: { minMs, maxMs } })`, an SSE parser that handles `data:` frames split across chunks, `:` comments and CRLF, reconnects with `?since=<last ts>` and drops duplicates by `runId|type|ts` (the server's own dedupe key, see `apps/server/src/sse.ts`); and `replayFile(path, { speed })`, which reads a JSONL recording (validated with `StarlingEventSchema`) for demos and dry runs.
6. **CLI** `notify.ts`: `bun integrations/notify/notify.ts [--server http://127.0.0.1:7777 | --file run.jsonl [--speed 50]] [--run <id>] [--webhook <url> | env STARLING_NOTIFY_WEBHOOK] [--format slack|discord|generic] [--macos] [--dry-run] [--rate 6] [--burst 3] [--only merged,audit-failed,run-finished]`. Sends `x-flock-token` when `STARLING_TOKEN` is set. Exits after `run.finished` with `--exit-on-finish`; Ctrl-C flushes pending messages.
7. **README.md:** Slack and Discord webhook setup, macOS permission notes (Script Editor notifications), a sample of each format, and how rate limiting behaves.
8. **Tests:** the milestone sequence for `fixtures/runs/sky-todo-launch-day.jsonl` (string asserts on kinds and counts, not a giant snapshot), limiter behaviour with a fake clock (burst, refill, digest, never dropping `bad`), each formatter including escaping and mention neutralising, webhook retries on 429/5xx with a fake `fetch`, URL redaction, AppleScript escaping in the argv, the SSE parser on split chunks/CRLF/comments, reconnect with `since` and dedupe across a dropped stream (a fake `fetch` serving two streams), and a `--dry-run --file` end-to-end through the CLI's exported `main(argv, io)`. At least 35 tests, under 3 s; no real network, no real `osascript`.
