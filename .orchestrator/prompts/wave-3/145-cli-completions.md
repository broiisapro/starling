## Goal
Small things that make a CLI feel finished: tab completion in bash, zsh and fish that always matches the real command tree (including every Wave 3 extension, because it's generated from commander at runtime), a `starling version --json` that a bug report can paste (Starling, Bun, opencode, git, gh, OS), and a tiny bird banner on `--help` in a real terminal. Great looks like: `eval "$(starling completions zsh)"` just works, the generated scripts pass `bash -n`/`zsh -n`, and nothing changes for pipes, CI or snapshot tests.

## Deliverables
1. `index.ts` exporting `extension` (`name: 'completions'`) whose `register()` adds **two** commands, `starling completions <shell>` (`bash|zsh|fish`, via commander `Option`/`Argument` choices) and `starling version [--json]`, and installs the help banner (item 7).
2. `tree.ts`: `describeProgram(program: Command): CliTree` walking `program.commands` recursively **at action time** (so commands registered after this extension are included): `{ name, summary, args: { name, required, variadic, choices? }[], options: { flags: string[], takesValue, choices?, description }[], subcommands: CliTree[] }`. Hidden commands/options are skipped; `help` is included.
3. `bash.ts`, `zsh.ts`, `fish.ts`: pure generators `renderBash(tree)`, `renderZsh(tree)`, `renderFish(tree)`. Complete subcommands, long and short options per subcommand, option choices (e.g. `init --profile auto|opencode|deepseek|local`), and files for path-like options (`--repo`, `--file`, `--record`, `--worktree-root`, any option whose value name contains `path`, `file` or `dir`) and for `*.jsonl` positional args (`replay`, `watch`, `report`, `explain`). The zsh output is a proper `#compdef starling` script with `_arguments` descriptions; bash uses `complete -F` and works on macOS's bash 3.2 (no `mapfile`, no associative arrays); fish uses `complete -c starling -n '__fish_use_subcommand'` / `__fish_seen_subcommand_from`.
4. Install hints: `starling completions <shell> --install-hint` prints the one line to add (`eval "$(starling completions zsh)"` for `~/.zshrc`, `source <(starling completions bash)` for bash, `starling completions fish > ~/.config/fish/completions/starling.fish`). The command never writes into the user's dotfiles.
5. `version.ts`: `collectVersions(deps): Promise<VersionReport>` with `{ starling: string, bun: string, opencode: string | null, git: string | null, gh: string | null, os: { platform, arch, release } }`. Starling's version comes from `program.version()` (or `STARLING_VERSION` env when set: the packaging epic 151 may inject it); tools are probed with core `exec` (`opencode --version`, `git --version`, `gh --version`), 3 s timeout each, run in parallel, missing binary or timeout → `null`, versions parsed to bare semver-ish strings by tolerant regexes (keep the raw first line in `--json` under `raw`).
6. `starling version` prints an aligned human block (with ✓/✗ marks and a hint for missing `opencode`); `--json` prints exactly one JSON object. Exit 0 even when tools are missing.
7. `banner.ts`: `renderBanner({ ascii, width })`: a 3–4 line bird + "Starling" wordmark with the tagline, ≤ 60 columns, ASCII fallback. Install it with `program.addHelpText('beforeAll', () => …)` **only when** `process.stdout.isTTY` and `STARLING_NO_BANNER` is unset and `NO_COLOR`-safe (plain text when colour is off). So existing help snapshot tests (non-TTY) are unaffected; prove that with a test.
8. `try.ts`: builds a demo program (a few fake commands mirroring the real ones: `plan <goal> --repo --json`, `replay <file> --speed`, `init --profile <choice>`) plus this extension, so `bun apps/cli/src/ext/completions/try.ts completions zsh` works before C3.
9. Tests (≥ 30): tree walk incl. nested subcommands, hidden options skipped, choices captured; each generator snapshot on the demo tree; `bash -n` and `zsh -n` syntax checks of generated scripts via `exec` (skip the zsh/fish check with `test.skipIf` when the shell isn't installed); a bash completion behaviour test (source the script in `bash -c`, set `COMP_WORDS`/`COMP_CWORD`, call the function, assert `COMPREPLY`); version parsing for real-world outputs (`git version 2.47.1 (Apple Git-154)`, `gh version 2.82.0 (2026-09-30)`, `opencode 2.1.4`), missing tool → null, `--json` purity, banner only in TTY.
